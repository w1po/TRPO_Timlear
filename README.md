# Purity — королевский клининг-сервис в Беларуси

Веб-приложение для заказа клининговых услуг на **Node.js + Express**.
Три независимых модуля, инкапсуляция работы с JSON и явные связи
через `require` / `module.exports`.

Основной пакет уборки необязателен: клиент может заказать только
дополнительные услуги — мытьё окон, химчистку дивана, уборку балкона
или мытьё техники внутри.

Стоимость рассчитывается в белорусских рублях (**BYN**), контактный номер —
белорусский: **+375 (29) 111-22-33**.

## Быстрый запуск

```bash
npm install
npm start
```

Приложение откроется по адресу **http://localhost:3000**.

При первом запуске модули сами создают каталог `data/` и JSON-файлы:

| Роль | Логин | Пароль |
|------|-------|--------|
| Администратор | `admin` | `admin123` |
| Клиент | `user@mail.ru` | `123456` |

> Пароли хранятся только в виде scrypt-хеша с индивидуальной солью.
> Оплата картой — демонстрационная заглушка, реального списания нет.

## Выбор адреса и времени

- Адрес уборки можно выбрать на встроенной карте **Leaflet** с тайлами
  **OpenStreetMap**. Поиск и обратное геокодирование выполняет бесплатный
  **Nominatim** — API-ключи не нужны.
- Дата выбирается в кастомном календаре (прошедшие дни недоступны), время —
  в сетке слотов `09:00`, `10:00`, `11:30`, `13:00`, `14:30`, `16:00`,
  `17:30`, `19:00`. Выбор сразу отражается в блоке «Итого».
- Основные пакеты и вариант «Без основного пакета (только доп. услуги)»
  расположены в сетке 2×2; на мобильных — в одну колонку.

## Модульная архитектура

### `modules/authModule.js`

**Публичный интерфейс — только два метода:**

- `register(userData)` — регистрация клиента, проверка e-mail и белорусского
  номера телефона, хеширование пароля через `crypto.scryptSync`;
- `login(login, password)` — вход по логину или e-mail, безопасное сравнение
  хешей через `timingSafeEqual`.

**Скрыто внутри модуля:** путь к `data/users.json`, чтение/атомарная запись
файла, создание дефолтных пользователей, валидация, нормализация номера
телефона к формату `+375 (XX) XXX-XX-XX`, хеширование и удаление приватных
полей из ответа.

### `modules/calculatorModule.js`

**Публичный интерфейс — четыре метода:**

- `getServices()` — пакеты («Базовая», «Генеральная», «После ремонта»),
  дополнительные услуги и коэффициенты помещений
  (Квартира ×1, Дом ×1.5, Офис ×1.3);
- `calculateBreakdown(propertyType, area, packageId, extraServiceIds)` —
  детализированный серверный расчёт: пакет, доп. услуги, промежуточные суммы;
- `calculateTotal(propertyType, area, packageId, extraServiceIds)` — итог
  в белорусских рублях: `цена за м² × площадь × коэффициент + доп. услуги`;
- `updateTariff(packageId, newPrice)` — изменение цены пакета администратором.

Тарифы по умолчанию: «Базовая» — 4 Br/м², «Генеральная» — 7 Br/м²,
«После ремонта» — 11 Br/м². Дополнительные услуги: мытьё окон — 25 Br,
химчистка дивана — 60 Br, уборка балкона / лоджии — 35 Br,
мытьё холодильника и духовки внутри — 30 Br.

**Скрыто внутри модуля:** файл `data/services.json`, валюта `BYN`, тарифы
по умолчанию, мягкая миграция доп. услуг, глубокое копирование данных,
валидация площади, пакета и цен.

### `modules/orderModule.js`

**Публичный интерфейс — только четыре метода:**

- `createOrder(orderPayload)` — создаёт заказ (с пакетом или только с доп.
  услугами), генерирует уникальный номер квитанции
  `PR-ГГГГММДД-0001` и всегда ставит статус **«Оплачен»**;
- `getOrdersByUser(userId)` — заказы клиента для личного кабинета;
- `getAllOrders()` — все заказы для администратора;
- `changeOrderStatus(orderId, newStatus)` — смена статуса с записью в историю.

**Скрыто внутри модуля:** файл `data/orders.json`, список допустимых статусов,
генерация идентификаторов и последовательности квитанций, сортировка, запись.

### `server.js`

- Импортирует три модуля через `require`.
- Настраивает Express, JSON-body, раздачу `public/` и SPA-fallback.
- Хранит сессии в памяти и выдаёт токены `Bearer`.
- При оплате **не доверяет сумме из браузера**: вызывает
  `calculatorModule.calculateBreakdown(...)` и передаёт проверенные
  пакет, доп. услуги и `total` в `orderModule.createOrder(...)`.
- Проверяет права: клиент видит только свои заказы, тарифы и статусы
  всех заказов меняет только администратор.

## REST API

| Метод | Маршрут | Доступ | Назначение |
|-------|---------|--------|------------|
| POST | `/api/auth/register` | все | регистрация |
| POST | `/api/auth/login` | все | вход |
| GET | `/api/auth/me` | токен | текущий пользователь |
| POST | `/api/auth/logout` | токен | выход |
| GET | `/api/services` | все | тарифы и коэффициенты |
| POST | `/api/orders` | клиент | создание оплаченного заказа |
| GET | `/api/orders/my` | клиент | свои заказы |
| POST | `/api/orders/:id/cancel` | клиент | отмена оплаченного заказа |
| GET | `/api/admin/orders` | админ | все заказы |
| PATCH | `/api/admin/orders/:id/status` | админ | смена статуса |
| PUT | `/api/admin/tariffs/:packageId` | админ | изменение цены |

## Сценарий демонстрации

1. Выбрать тип помещения и площадь — блок «Итого» пересчитается автоматически.
2. Выбрать адрес на карте, дату в календаре и слот времени, затем пакет
   и/или доп. услуги.
3. Нажать «Оплатить», войти как клиент и подтвердить демо-оплату.
4. Показать виртуальную квитанцию с пакетом и доп. услугами; она же доступна
   в личном кабинете.
5. Войти как `admin`, сменить статус заказа и цену тарифа.
6. Убедиться, что новый тариф сразу применяется в калькуляторе.

## Особенности реализации

- В каждом модуле чётко разделены **публичный интерфейс** и **скрытая реализация**.
- Файлы JSON не читаются за пределами «своего» модуля — детали хранения инкапсулированы.
- Связи между модулями явные: только через `require` и экспортированные методы.
- Бизнес-логика расчёта и статусов находится на сервере, а не в браузере.
- Пароли не хранятся в открытом виде; роль `admin` нельзя получить при регистрации.
- Все цены отображаются в белорусских рублях, телефоны — в формате `+375`.
- Данные создаются автоматически, поэтому проект запускается на чистой машине.
